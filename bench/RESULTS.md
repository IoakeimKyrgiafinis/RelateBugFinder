# Real-bug benchmark: BugsInPy

Generated by `node bench/report.mjs` from `bench/results/bugsinpy.jsonl` (229 bugs attempted).

**Setup.** [BugsInPy](https://github.com/soarsmu/BugsInPy) (Widyasari et al., ESEC/FSE 2020) is a published set of real bugs from real Python projects, each with the buggy commit, the fix commit and the test that exposes the bug. For every bug, `bench/bugsinpy.mjs` checks out the buggy commit with its real git history, adds the failing test from the fix (committed with an old date so it carries no "recent change" signal), runs it on Python 3.8 / Windows 11, and gives the resulting output to each method below with the clock pinned to the buggy commit's time.

**Ground truth.** The functions whose lines the real fix changed (test files excluded). A method "hits at top k" if any of them is in its first k suggestions. MRR = mean of 1/rank (0 when not found).

**Tuning.** Blast Radius's weights (src/core/analysis.ts `SCORING`) were picked by `node bench/tune.mjs` on a fixed DEV half of the bugs (split by a hash of the bug name). The first table below is the other half, which played no part in choosing them.

**Methods compared.** Blast Radius, and three baselines computed from the same trace and graph: reading the stack top-down; the stack frames re-ordered by most recent change (what Sentry's "suspect commits" uses); and the most recently changed functions in the project, ignoring the trace.

## Reproduction

4 reproduced bug(s) are excluded from scoring because the fix only changed module-level code (no function to point at).
